# Feature Specification: GEO Insight 品牌可见度监测平台

**Feature Branch**: `001-geo-insight-platform`

**Created**: 2026-11-11

**Status**: Draft

**Input**: User description: "把 GEO Insight 整体方案和 2026-11-11 的澄清记录收成第一版规格。首版只做监控、指标、报告；核心问题每天采 3 次、长尾每天 1 次；平均排名按答案推荐清单的序号；当前阶段只出方案，不做真实采集。产品面向品牌方与代理商，用来跟踪品牌在 AI 答案里被提及、被推荐、被引用的情况。"

## Clarifications

### Session 2026-11-11

- Q: 品牌位次按什么定义为「第几名」？ → A: 列表序号（答案推荐清单/编号列表中的序号；无列表结构的答案不计入平均排名，单独计「无列表样本」）
- Q: 首期是否需要真实网页端采集？ → A: 不需要，当前阶段只出方案，不做真实采集
- Q: 每个问题每个模型每天采几次？ → A: 核心问题 3 次/日，长尾问题 1 次/日
- Q: 第一个可交付版本做到哪一步？ → A: 监控 + 指标 + 报告
- Q: 核心/长尾问题如何分层？ → A: 人工指定

### Session 2026-11-11（分析后修订）

- Q: 「首次成功率 ≥ 90%」如何测量？ → A: 以 10 名试用运营为样本，其中 ≥9 人能在 10 分钟内独立完成「建对象 → 导入 20 个问题 → 标记 5 个核心」，由观察记录判定；不做产品内埋点。
- Q: 采样失败率的分母与告警阈值？ → A: 失败率 = 失败的 run_item 数 / 全部 run_item 数；阈值 10%，超过时在看板与配置页提示，失败项不进入任何指标分母。
- Q: 原始答案批量导出用什么格式、含哪些列？ → A: CSV（UTF-8 BOM，Excel 直接可读）与 JSONL 两种；列固定为 answer_id、日期、采集时间、问题、层级、模型、通道、是否提及、位次、情感、片段、引用数、答案原文。
- Q: 「PDF 与页面一致率 100%」怎么验收？ → A: 逐字段比对报告页与导出 PDF 中的 6 个指标值、周期、样本量、口径版本、生成时间与不可比原因；布局与字体不比对。PDF 由浏览器打印生成。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 查看品牌在 AI 答案中的表现（Priority: P1）

品牌负责人打开某个监控对象，想在一屏内回答一个问题：我的品牌最近在 AI 答案里表现如何。他看到提及数、提及率、平均排名、Top1/Top3/Top10 与情感分布，并能下钻到具体问题、具体模型、具体那次答案的原文与引用来源，判断数字是否可信。

**Why this priority**: 这是产品的存在理由。没有可信的看板，后面的诊断、内容、报告都没有依据。只做这一个故事，也已经能交付「看得见」的价值。

**Independent Test**: 准备一个监控对象与一组已导入的样本数据，打开详情页，能在 3 次点击内从指标卡下钻到某条答案原文；指标与样本数据可手工核对一致。

**Acceptance Scenarios**:

1. **Given** 监控对象有 3 天有效样本，**When** 用户打开指标看板，**Then** 显示提及数、提及率、平均排名、Top1/Top3/Top10、正/中/负情感占比，并标明样本量与统计周期。
2. **Given** 统计周期为 3 天，某问题在 3 个模型下共 9 个有效样本、其中 2 个提到品牌，**When** 用户查看该问题的提及率，**Then** 显示 22.2%（2/9）并可展开看到是哪 2 个样本。
3. **Given** 某个答案里品牌只出现在正文段落、没有推荐列表，**When** 用户查看平均排名，**Then** 该样本不计入平均排名，页面显示「无列表样本 N 条」。
4. **Given** 某问题只有 2 个有效样本，**When** 用户查看提及率，**Then** 页面显示「样本不足」，而不是 0% 或 100%。

---

### User Story 2 - 配置监控对象与问题集（Priority: P2）

运营要为一个新客户建立监控：输入品牌名与别名、行业与地区，导入一批用户真实会问的问题，把其中最重要的标为核心问题，保存后系统按核心 3 次/日、长尾 1 次/日安排采样。

**Why this priority**: 没有配置就没有数据。但它依赖 P1 的展示才有意义，所以排在 P1 之后，且可以独立测试（配置完能看到「待采样」状态与问题数）。

**Independent Test**: 从空白开始创建一个监控对象、导入 20 个问题、标记 5 个核心，保存后列表页正确显示问题数与核心/长尾数量，不需要任何已有数据。

**Acceptance Scenarios**:

1. **Given** 用户新建监控对象，**When** 只填写品牌名与行业就保存，**Then** 系统允许保存但提示「尚未绑定问题集，不会产生数据」。
2. **Given** 用户导入 20 个问题并标记 5 个为核心，**When** 保存问题集，**Then** 监控详情显示问题总数 20、核心 5、长尾 15。
3. **Given** 用户把某问题从长尾改为核心，**When** 查看采样计划，**Then** 该问题的日采样次数从 1 变为 3，且变更从次日生效，不回改历史数据。
4. **Given** 两个问题文本完全相同，**When** 用户导入，**Then** 系统提示重复并只保留一条。

---

### User Story 3 - 生成并交付周期报告（Priority: P3）

客户成功或管理者选择一个时间周期，生成一份可对外发送的报告：包含指标概览、趋势、信源分布与结论页，导出 PDF。报告里的每个数字都能追溯到样本量与口径版本，遇到不可比的情况会明确标注。

**Why this priority**: 报告是交付物，但必须建立在 P1 的指标可信、P2 的配置完整之上。它可以独立测试（给定已聚合数据，能生成并导出）。

**Independent Test**: 选一个已有数据的周期，生成报告并在 60 秒内导出 PDF；PDF 中的指标与看板一致，且包含样本量、口径版本、生成时间。

**Acceptance Scenarios**:

1. **Given** 选定周期内有 5 天数据，**When** 用户生成报告，**Then** 报告包含指标概览、趋势图、信源类型分布、Top 媒体、结论页与样本量说明。
2. **Given** 对比周期内模型集合发生变化，**When** 用户生成对比报告，**Then** 报告标注「模型不一致，不可直接比较」，且不给出涨跌百分比。
3. **Given** 报告已生成 30 天，**When** 用户再次打开，**Then** 显示的数字与生成时一致，不随之后的数据变化。
4. **Given** 报告生成失败，**When** 用户重试，**Then** 不重复扣减额度，且能看到失败原因。

---

### Edge Cases

- 答案里没有任何推荐列表：位次记为空，归入「无列表样本」，不参与平均排名与 TopN；页面必须显示这类样本的占比。
- 同一个答案里品牌出现 3 次：提及数计 1 次；情感按品牌相关片段分别判断后取主导情感，并在明细里保留片段。
- 品牌只出现在否定句（例如「A 不如 B」）：仍计为提及，情感判为负面，不因为「提到了」就算正面。
- 采样失败（超时、限流、拒答、空答案）：不计入有效样本与分母，单独统计失败率；失败率超过阈值时在看板提示。
- 样本量低于 3：显示「样本不足」，不显示百分比结论。
- 问题被删除或停用：历史样本保留，看板按历史口径展示；后续不再产生新样本。
- 竞品集合变更：历史指标不重算，报告注明竞品集合版本；新周期按新集合计算。
- 引用来源时间无法识别：归入「未知」桶，不猜测；「未知」占比超过 50% 时在信源页提示数据质量。
- 同一 URL 在一个答案里被引用多次：引用次数按出现次数累计；媒体排行按出现次数；内容明细按 URL 去重展示。
- 报告周期内口径版本发生变化：报告标注版本差异，不把两个版本的数字直接相减。

## Requirements *(mandatory)*

### Functional Requirements

**监控配置与资产**

- **FR-001**: 用户 MUST 能创建、编辑、停用监控对象，包含品牌名称、行业、地区、状态与负责人。
- **FR-002**: 用户 MUST 能维护品牌别名（简称、英文名、常见错写），用于答案中的品牌识别。
- **FR-003**: 用户 MUST 能维护竞品集合，并在答案明细中标注竞品出现；首版不提供竞品对比指标，但指标快照 MUST 记录所用竞品集合的版本，供后续扩展。
- **FR-004**: 用户 MUST 能创建问题集、批量导入问题，并为每个问题设置 `core` 或 `long_tail` 层级。
- **FR-005**: 系统 MUST 在导入时识别完全重复的问题并提示，重复项不写入。
- **FR-006**: 用户 MUST 能把问题集绑定到一个监控对象，并在列表与详情展示问题总数、核心数、长尾数。
- **FR-007**: 监控对象未绑定问题集时，系统 MUST 允许保存，但明确提示「不会产生数据」。

**采样**

- **FR-008**: 系统 MUST 按「核心问题 3 次/日、长尾问题 1 次/日」为每个「问题 × 模型」生成采样计划。
- **FR-009**: 每条采样记录 MUST 保存问题、模型、通道、采样时间、当日第几次采样、状态与失败原因。
- **FR-010**: 采样失败 MUST 不计入有效样本，也不进入任何指标的分母。失败率 MUST 按「失败的采样执行数 / 全部采样执行数」计算并可查看；失败率超过 10% 时 MUST 在看板与配置页提示，且提示中必须给出失败数与总数。
- **FR-011**: 用户 MUST 能对单个问题手动触发一次补采，补采记录 MUST 与定时采样可区分。
- **FR-012**: 问题层级变更 MUST 从次日生效，不回溯修改历史采样次数。

**解析与口径**

- **FR-013**: 系统 MUST 识别答案中出现的品牌提及，覆盖品牌全称、别名与常见错写。
- **FR-014**: 系统 MUST 判定提及位次：品牌出现在答案的推荐清单或编号列表中时，取该列表项的序号（从 1 开始）。答案有多个列表时，取品牌首次出现的那个列表，序号以该列表为基准；品牌只在正文出现时位次为空。
- **FR-015**: 平均排名 MUST 只统计位次非空的提及样本；TopN MUST 使用「位次 ≤ N 的样本 / 位次非空的样本」计算，不得把无列表样本算进分母。无列表样本占提及样本的比例超过阈值（默认 50%，由 `GET /v1/meta/methodology` 下发、可配置）时，系统 MUST 在看板给出数据质量提示，并说明占比与阈值。
- **FR-016**: 提及率 MUST 按「提及样本数 / 有效样本数」计算，分母是样本；覆盖率 MUST 按「有提及的问题数 / 当前启用且已绑定问题集的问题数」计算，分母是问题。两者在页面上必须分别命名、不得混用。
- **FR-017**: 情感判定 MUST 输出正面、中性、负面三类，并以「品牌相关片段」为单位，而不是整篇答案。同一答案内多个片段情感不一致时，按片段数量取多数；平票时按「负面 > 中性 > 正面」的保守顺序取值，并在明细保留全部片段。情感分布的分母 MUST 为提及样本数，未提及品牌的答案不得计入。
- **FR-018**: 有效样本数低于 3 时，系统 MUST 显示「样本不足」，不得显示 0%、100% 或平均排名结论。每个指标 MUST 按自身分母独立判断：提及率看有效样本数，平均排名与 TopN 看位次非空的样本数，情感看提及样本数。
- **FR-019**: 系统 MUST 为每次指标计算记录口径版本，并允许用户在页面查看口径说明（分母、位次定义、去重规则）。
- **FR-020**: 同一答案中品牌多次出现时，提及数 MUST 只计 1 次；引用次数 MUST 按 URL 出现次数累计，内容明细 MUST 按 URL 去重。

**看板与明细**

- **FR-021**: 用户 MUST 能在监控详情查看指标卡：提及数、提及率、平均排名、Top1/Top3/Top10、正/中/负情感占比，并显示样本量与统计周期。
- **FR-022**: 用户 MUST 能按问题、模型、日期、引用类型筛选问答明细，并查看答案原文与引用来源。
- **FR-023**: 用户 MUST 能从任一指标下钻到构成该指标的样本列表，再下钻到单条答案。
- **FR-024**: 用户 MUST 能查看趋势分析，按日或按周展示指标变化；模型集合发生变化时 MUST 在趋势上标注变更点。
- **FR-025**: 用户 MUST 能查看信源分布：媒体类型分布、发布时间分布、媒体排行、内容明细。
- **FR-026**: 信源时间无法识别时，系统 MUST 归入「未知」并在页面显示其占比，不得推测补齐。

**报告**

- **FR-027**: 用户 MUST 能选择周期生成报告，报告包含指标概览、趋势、信源分布、结论页、样本量与口径版本。
- **FR-028**: 报告 MUST 是生成时刻的不可变快照，30 天后打开数字不变。
- **FR-029**: 对比周期内模型集合、竞品集合或口径版本不一致时，报告 MUST 标注「不可比」，且不输出涨跌幅。
- **FR-030**: 用户 MUST 能把报告导出为 PDF，导出内容与页面展示一致。
- **FR-031**: 报告生成失败 MUST 可重试，重试不得产生重复报告，也不得重复占用系统配额。

**访问与数据**

- **FR-032**: 系统 MUST 区分管理员、运营、只读三种角色；只读角色不得修改配置或触发采样。
- **FR-033**: 所有业务数据 MUST 带监控对象归属；用户只能看到自己有权访问的监控对象。
- **FR-034**: 原始答案与引用记录 MUST 至少保留 180 天，且可按监控对象批量导出。导出 MUST 支持 CSV（UTF-8 BOM）与 JSONL 两种格式，列至少包含答案原文、问题、模型、通道、采集时间、是否提及、位次、情感与引用数；导出不得修改原始记录。
- **FR-035**: 删除监控对象 MUST 先进入停用状态，历史数据保留；彻底删除需二次确认并记录操作人。

### Key Entities

- **监控对象（Tracker）**：一个品牌在一个行业/地区的监控单元，包含状态、负责人、绑定的竞品集合与问题集。
- **品牌与别名（Brand / Alias）**：被监控的主体，一个品牌可有多个别名，用于提及识别。
- **竞品（Competitor）**：与品牌同场比较的对象集合，带版本，变更不影响历史指标。
- **问题（Question）**：用户真实会问的一句话，带层级（core / long_tail）、意图标签与状态。
- **问题集（Question Set）**：一组问题的集合，绑定到监控对象。
- **采样样本（Sample）**：一次「问题 × 模型 × 通道 × 当日第 N 次」的执行记录，包含状态、时间、失败原因。
- **答案（Answer）**：一次采样得到的完整回答，包含原文、模型标识、采集时间；是追溯的最小单位。
- **提及（Mention）**：品牌在某个答案中的一次出现判断，包含位次、片段与情感。
- **引用（Citation）**：答案引用的一个来源，包含 URL、媒体、位置与引用类型。
- **指标快照（Metric Snapshot）**：某监控对象在某周期内的聚合结果，带口径版本与样本量。
- **报告（Report）**：基于指标快照生成的不可变交付物，带周期、版本与导出状态。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 10 名未接触过系统的运营中，≥9 人能在 10 分钟内独立完成「建监控对象 → 导入 20 个问题 → 标记 5 个核心」，且无需他人代为操作。
- **SC-002**: 打开监控详情看板，95% 的请求在 2 秒内返回首屏指标。
- **SC-003**: 提及判定与人工标注的一致率 ≥ 90%；情感判定一致率 ≥ 85%（以 200 条人工标注答案为基准）。
- **SC-004**: 任一指标都能在 3 次点击内下钻到构成它的样本列表与单条答案原文。
- **SC-005**: 生成一份周期报告 ≤ 60 秒；按「6 个指标值 + 周期 + 样本量 + 口径版本 + 生成时间 + 不可比原因」逐字段比对，打印导出的 PDF 与报告页一致率 100%（不比对字体与布局）。
- **SC-006**: 100% 的报告数字可追溯到样本量、口径版本与生成时间；不可比场景 100% 有标注。
- **SC-007**: 有效样本低于 3 的场景，100% 显示「样本不足」，不出现 0% 或 100% 的误导性结论。
- **SC-008**: 任意指标页面都能在 2 次点击内打开口径说明，说明中包含分母、位次定义与去重规则。

## Assumptions

- 首版面向单团队内测，不做代理商多租户、不做 Credits 计费；数据结构需保留归属字段，避免后续迁移。
- 首版验收可使用人工采样或模拟样本，不要求真实采集系统上线；真实采集的可行性在进入实现阶段前另行验证。
- 监控对象以国内 AI 平台为主，海外模型不在首版范围。
- 单个监控对象的问题数不超过 500；超过时需拆分监控对象。
- 问题层级由运营人工指定，系统不自动推断核心/长尾。
- 竞品集合由人工维护，首版不做自动竞品发现。
- 无推荐列表的答案会占一定比例，首版接受该限制，但必须单独展示占比，不能混入平均排名。
- 首版不包含：优化机会、优化任务、内容工作室、任务发布、AI 助手、自动竞品发现、多租户计费。
- 首版验收前由产品与运营共同标注 200 条答案作为基准集，标注规范随口径说明一同发布。
- 用户具备基本的 AI 对话使用经验，理解「同一个问题多次提问，答案可能不同」。
