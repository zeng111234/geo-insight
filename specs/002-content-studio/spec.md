# Feature Specification: 内容工作室与多渠道发布

**Feature**: `002-content-studio`
**Status**: Draft（首版只做界面与占位接口，不接真实自动化）
**Created**: 2026-11-11
**依据**：用户提供的「创作工作台」截图 + 两条核心功能要求

## 0. 背景与范围

用户在 001（监控 + 指标 + 报告）之上新增一条闭环：**写稿 → 发布到各渠道 → 看发布后提及率**。

首版明确的边界：

- **只做界面与数据形态**，不接 Playwright、不做真实登录、不做真实发布。按钮可以点，但要如实返回「待接入」。
- 两条核心功能必须可见：
  1. **发布后提及率**：文章发布后，品牌在 AI 答案里的提及率与发布前的对比；
  2. **渠道登录与一键发布**：在系统内绑定各平台账号，选渠道后一键发布。

## 1. User Scenarios

### User Story 1 - 在同一个界面里写稿（Priority: P1）

运营打开内容工作室，左边是这次写作的要求（针对哪个问题、优化目标、验收条件、品牌资料、事实校验阈值），中间编辑正文，右边核对事实与证据来源。三栏同屏，不用来回跳页面。

**Acceptance Scenarios**

1. **Given** 某文章处于草稿状态，**When** 打开内容工作室，**Then** 三栏同时渲染：创作要求、正文编辑、事实与证据，且都带该文章的真实字段。
2. **Given** 正文被修改，**When** 点击保存，**Then** 标题与正文落库，版本号 +1，页面显示「已保存」。
3. **Given** 文章有一条「待核实」事实，**When** 查看右侧面板，**Then** 该事实排在「已确认」之前并标黄，提示补充证据后才能审核。

### User Story 2 - 绑定渠道并一键发布（Priority: P2）

运营在发布面板看到各平台账号状态，未连接的先连接（首版为占位流程），已连接的勾选后点「一键发布」，系统为每个渠道生成一条发布记录并显示状态。

**Acceptance Scenarios**

1. **Given** 7 个平台中有 2 个未连接，**When** 点击该平台的「连接」，**Then** 状态变为已连接并记录连接方式，页面提示「展示态，未接入真实登录」。
2. **Given** 已勾选 3 个已连接渠道，**When** 点击「一键发布」，**Then** 生成 3 条发布记录，状态为 `queued`，页面显示每条的归属渠道。
3. **Given** 有渠道未连接，**When** 勾选它并发布，**Then** 前端禁用该选项，后端返回 400 并指出具体渠道。

### User Story 3 - 看发布后提及率（Priority: P1）

文章发布后，运营在工作室底部看到「发布前 vs 发布后」的提及率对比，含样本量。样本不足时不给结论。

**Acceptance Scenarios**

1. **Given** 文章发布于 2026-11-04，**When** 查看对比，**Then** 发布前窗口为 11-01~11-03（9 样本、2 提及、22.2%），发布后为 11-04~11-05（5 样本、2 提及、40%），显示 +17.8pp。
2. **Given** 发布后窗口样本数 < 3，**When** 查看对比，**Then** 显示「样本不足」而不是 0% 或 100%，且不输出涨跌。
3. **Given** 文章未发布，**When** 查看对比，**Then** 显示「未发布，无对比数据」。

## 2. Functional Requirements

### 内容与创作

- **FR-001**: 系统 MUST 提供内容工作室页面，同屏呈现创作要求、正文编辑、事实与证据三栏。
- **FR-002**: 每篇文章 MUST 保存创作要求：关联问题、内部简报、优化目标、验收条件、品牌资料、事实校验阈值。
- **FR-003**: 文章 MUST 有标题、正文、模板、状态（draft/review/published）与版本号；保存正文时版本号 MUST 递增。
- **FR-004**: 系统 MUST NOT 提供 AI 成稿入口，也 MUST NOT 引入积分/计费（决策 003）。正文由人工撰写；AI 仅允许用于「基于诊断回答的提纲建议」，且本期不实现。页面 MUST 明示「人工成稿 · 系统只做事实核对与合规提示」。
- **FR-005**: 事实条目 MUST 分「已确认 / 待核实 / 驳回」三态，并记录来源；「待核实」MUST 排在「已确认」之前。
- **FR-006**: 正文命中合规风险词时 MUST 在编辑区给出提示，且提示不阻断保存。

### 渠道与发布

- **FR-007**: 系统 MUST 列出可发布渠道及账号状态（已连接/未连接/已过期）、连接方式与最近检查时间。
- **FR-008**: 用户 MUST 能对单个渠道发起连接；首版为占位流程，成功后状态置为已连接并 MUST 标注「展示态，未接入真实登录」。
- **FR-009**: 用户 MUST 能勾选一个或多个已连接渠道一键发布；未连接渠道 MUST 被拒绝，错误响应 MUST 指出具体渠道。
- **FR-010**: 每次发布 MUST 为「文章 × 渠道」生成一条记录，含状态（queued/published/failed）、发布时间、失败原因与回链 URL。
- **FR-011**: 同一篇文章对同一渠道重复发布时，MUST 复用未开始的记录，不得产生重复队列项。

### 发布后效果

- **FR-012**: 系统 MUST 按文章发布时间切分窗口，给出「发布前 / 发布后」提及率与样本量；窗口长度默认各 3 天，可配置。
- **FR-013**: 任一窗口样本数 < 3 时，该窗口 MUST 显示「样本不足」，且 MUST NOT 输出涨跌幅。
- **FR-014**: 对比结果 MUST 标注所用统计窗口与口径版本，供追溯。
- **FR-015**: 只有存在 `published` 记录的文章才参与对比；未发布文章 MUST 显示「未发布，无对比数据」。

### 约束

- **FR-016**: 首版 MUST NOT 引入 Playwright、无头浏览器或任何自动登录/自动发帖能力。
- **FR-017**: 所有写操作 MUST 标注数据来源为「演示」，避免被误认为已真实发布。

## 3. Success Criteria

- **SC-001**: 打开工作室，三栏与两条核心功能区块在 2 秒内渲染完成。
- **SC-002**: 示例文章（发布于 2026-11-04）的发布前后对比为 22.2% → 40.0%，与手算一致。
- **SC-003**: 任一窗口样本不足时，页面 100% 显示「样本不足」，不出现 0%/100%。
- **SC-004**: 点击「一键发布」后 1 秒内看到每渠道记录状态，且刷新页面后记录仍在。
- **SC-005**: 页面上区分「已接入」与「展示态」，不出现「已发布到公众号」这类未发生的表述。

## 4. Key Entities

| 实体 | 关键字段 | 说明 |
|---|---|---|
| article | id, tracker_id, title, body, template_key, status, version, brief, goal, acceptance, compliance_note | 文章与创作要求 |
| article_fact | id, article_id, claim, verdict, source_ref | 事实与证据 |
| channel_account | id, platform_key, platform_name, account_name, status, login_mode, last_checked_at | 渠道账号 |
| publication | id, article_id, channel_id, status, published_url, published_at, failure_reason | 发布记录 |

## 5. Assumptions

- 首版数据为演示数据，`geo.db` 中预置 3 篇文章与 7 个渠道。
- 渠道登录与真实发布需要各平台授权，故一律用占位流程，接口返回 `pending_integration`。
- 发布后提及率直接复用 001 的提及口径（提及样本 / 有效样本），不引入新口径。

## 6. Out of Scope

- 真实登录、验证码、扫码、Cookie 管理
- 真实发帖、定时发布、失败重试
- AI 成稿与积分计费：按决策 003 **整体移除**，不是延后实现；页面上也不保留入口。
- 多租户与角色（沿用 001 的 FR-032/033 未完成状态）
