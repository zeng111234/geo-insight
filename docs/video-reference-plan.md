## 一、视频里是什么系统

一个本地部署（`127.0.0.1:8013/geo/...`）的 GEO SaaS 完整产品，不是 demo。

**一级导航**（`f100` 帧，左侧栏）

| 分组 | 菜单 |
|---|---|
| 工作台 | 首页、问题监控、AI 舆情 |
| 优化执行 | 优化机会、优化任务、内容工作室、任务发布 |
| 分析报告 | 报告中心 |
| 品牌资产 | 品牌资产 |
| 探索工具 | 行业信源分布 |

**全局元素**：右上角「9,318 Credits」+「AI 助手」按钮。积分是全系统的计价单位（内容工作室里「AI 生成草稿 5 积分」「生成视频脚本 5 积分」）。

**问题监控页 = 三栏工作台**（`f100`、`header` 帧）

```
[监控列表 19]        [对象详情]                        [抽屉/引用]
辽宁辽征律师事务所    ├ 对象头：名称 + 监控已开启/手动触发
惠策（广州）          │   创建时间/创建成员/数据更新时间/最近任务 15/15
小鹏汽车              │   按钮：下载报告 表格浏览 导出 刷新 暂停 删除 编辑
双鸿图                ├ 筛选：品牌 | 问题 | 模型 | 日期
取消管理测试品牌      ├ 10 个 tab ────────────────────────────────
精品零食              │  指标看板 问答明细 指标明细 趋势分析 竞品排名
中田健身工作室        │  信源分析 情感倾向 竞品统计 视频/图文引用 采集健康
极度健身工作室        └ 内容区（随 tab 切换）
```

**10 个 tab 的名称**（`tabbar` 帧放大确认，不是猜测）：
指标看板 / 问答明细 / 指标明细 / 趋势分析 / 竞品排名 / 信源分析 / 情感倾向 / 竞品统计 / 视频·图文引用 / 采集健康

**指标看板**（`cards` 帧）五个区块横排：
提问次数 25 → 提及率 0% → 平均排名 — → 高位曝光（Top1/Top3/Top10 各 0%，浅红块）→ 情感倾向（正常/中性/负面 横条）

**问答明细**（`detail` 帧）双栏对照：
左「回答内容」带工具条（回答 1/10、复制、截图、证据详情、纠正）；右「引用信源」带收录筛选（全部/已监控）+ 提示「文章监控尚未接入，仅展示已保存的引用证据」。

**添加问题监控**（`k840` 帧）右侧抽屉，字段：
行业 / 地区 / 核心词 / 竞品品牌（逗号分隔）→ 监控问题（多行，每行一条）→ **国内 AI 模型 16 个渠道**（豆包网页、豆包手机、千问网页、千问手机、DeepSeek 网页、DeepSeek 手机、元宝网页、元宝手机、百度文心网页、文心一言手机、Kimi 网页、Kimi 手机、夸克 AI 网页、Bing AI 网页、抖音 AI 网页…）
底部：取消 / 保存监控 / **保存并立即执行**

关键含义：**模型是「模型 × 端」的二维渠道**（网页/手机/APP 分别采集、分别对比），不是我们现在的「一个模型一个 key」。

**内容工作室**（`k570`、`r2260` 帧）是六阶段流水线：
信源研究 → 事实与证据 → 正文编辑 → 质量审核 → 渠道稿 → 发布
编辑页三栏：制作要求 | 正文编辑（含标题模板、正文模板）| 事实与证据 + 诊断原始回答

**AI 助手**（`r1460` 帧）右侧面板：
选监控对象 → 选模式（进行诊断/主动诊断/站内排查）→ 填目标（0/2000）→ 选问题 + 模型与设备 + 日期范围 →「确认分析范围」→ 后台分析并记积分。

## 三、五类结构性差距（加页面补不上）

### 差距 1：问题监控的容器形态
参考系统：左侧 19 个监控对象 → 中间 10 tab 详情 → 右侧抽屉。
我们：侧栏选页面 → 页面内选问题 → 看回答。**对象（tracker）不是导航主体，问题才是。**

影响：这不是加个 tab 栏就行，要重做 `monitor.html` 的数据加载与布局（三栏 + 对象切换 + tab 懒加载）。

### 差距 2：对象配置的字段维度
参考系统有 行业 / 地区 / 核心词 / 竞品品牌，以及「模型 × 端」16 个渠道。
我们：`tracker` 有 industry/region，没有「核心词」；模型是单一 `model_key`（doubao/deepseek/kimi），没有「端」。

影响：`sampling_plan.model_keys`、`answer.model_key`、指标口径全部要加一维 `device`。**动数据模型，不是动页面。**

### 差距 3：AI 体系（推翻了决策 003）
参考系统：全局 AI 助手 + 积分账本 + 内容生产流水线 + 质量审核。
我们：决策 003 明确「AI 成稿与积分整体取消，不是待办」。

影响：这是最大的范围变化。要么恢复，要么明确不做并接受与参考系统的形态差异。

### 差距 4：数据来源假设
参考系统有「采集健康」tab、「任务发布」、文章监控（未接入但留了位置），说明它有自己的采集管道和调度。
我们：`csv_bank` 离线兜底 + 手工/脚本导入，没有调度，没有「采集健康」的数据基础。

影响：参考系统里很多数字（15/15 最近任务、采集健康）我们现在没有数据源可填。

### 差距 5：交互密度
- 表格视图 / 阅读视图切换
- 右侧抽屉（添加监控、AI 助手、编辑）
- 行内「证据详情」「纠正」
- 复制、截图按钮
- 批量选择与分页

我们：基础表格 + 分页，没有抽屉、没有视图切换、没有行内纠正。

## 四、建议的推进批次

按「先对齐形态、再补数据维度、最后上 AI」的顺序，每批都能独立验收。

### 批次 A：问题监控工作台（本轮做｜对齐差距 1，不新增数据依赖）
把 `monitor.html` 从「问题列表 + 回答」改成三栏工作台。

**进度（2026-11-24）**：A1（对象列表 + 搜索）、A2（对象头）、A3（10 tab 壳 + URL 路由）、
A4（指标看板）、A5（双栏：左回答 / 右引用）、A6（指标明细）、A7（趋势分析）、A8（信源分析）、
A10（竞品排名 / 竞品统计，新增 ranking 与 cooccurrence 两个聚合接口）、A11 里的视频图文引用已完成。
剩 A9（情感倾向按模型拆分）与采集健康两个 tab。

为让竞品两个 tab 有真实数据，`seed_rich_period` 补了竞品提及（11-06 起，避开黄金窗口），
竞品在 `brand` 表里有 `kind='competitor'` 的行。实测黄金窗口 22.22% / 9 样本一字未变。

| 任务 | 数据来源 | 判据 |
|---|---|---|
| A1 左栏监控对象列表（名称/行业/区域/状态徽标/问题数） | `/v1/trackers` + `/questions` | 点对象切换，右侧全量刷新 |
| A2 对象头（创建信息、最近任务、按钮组占位） | `/v1/trackers/{id}` | 没有数据的字段显示「—」，不写假数字 |
| A3 10 个 tab 壳 + 路由（`?tab=answers`） | 纯前端 | 每个 tab 可达、刷新保住当前 tab、前进后退正常 |
| A4 指标看板 tab（5 块：提问次数/提及率/平均排名/高位曝光/情感倾向） | `/metrics/overview` 已有 | 黄金窗口 22.22% / 9 样本不变 |
| A5 问答明细 tab 改双栏（左回答/右引用） | `/answers` + `/citations` | 引用条数 = 该回答的 citation 行数 |
| A6 指标明细 tab | `/metrics/{metric}/samples` 已有 | 行数 = 该指标样本数 |
| A7 趋势分析 tab | `/metrics/trend` 已有 | 与现有趋势图数值一致 |
| A8 信源分析 tab | `/citations/summary` 已有 | 域名排名与现有信源页一致 |
| A9 情感倾向 tab | overview 的 sentiment + 新增按模型拆分 | 三档占比之和 = 100% |
| A10 竞品排名 / 竞品统计 tab | **新增聚合接口**（mention 按 competitor 聚合） | 竞品提及数之和 = mention 里 subject_type='competitor' 的行数 |
| A11 视频·图文引用 / 采集健康 tab | citations.media_type / sampling_plan 差额 | 没数据的显式说明「该维度需要 X，尚未接入」，不画空图 |

预计 4–5 人日（A10 两个聚合接口 + A6–A9 各接一个 tab，比原先估的 3–4 天多）。
这一批不碰数据模型，风险最低，但视觉变化最大。

**8 个 tab 的真实可用度**（已核对现有接口，不是估计）：

| tab | 现状 |
|---|---|
| 指标明细 / 趋势分析 / 信源分析 | 接口已就绪，直接接 |
| 情感倾向 | 总量有，按模型拆分要补 |
| 竞品排名 / 竞品统计 | 需要新写聚合接口（mention 表已有数据） |
| 视频·图文引用 | `citation.media_type` 有值，可用 |
| 采集健康 | 只能做「计划 vs 已导入」，没有真实采集链路 |

**改造后的页面归属**（避免同一份数据两个入口）

| 现有页面 | 改造后 |
|---|---|
| `monitor.html` | 变成三栏工作台，10 个 tab 都在这一页里 |
| `answer.html` | 保留为「单条回答详情」，从问答明细 tab 点进去；本来就不在侧栏 |
| `index.html` | 保留。首页仍是跨对象的全局总览，与「问题监控看某对象」分工不同 |
| `insight.html` | 保留，对应参考系统的「AI 舆情」 |
| `sources.html` | 保留，对应「行业信源分布」 |
| `settings.html` | 保留，对应对象头右上角的「问题设置」，两个入口指向同一页 |

这意味着改造完侧栏不会多出菜单项，`monitor` 一个页面承载 10 个维度——和参考系统一致。

### 批次 B：对象配置与数据维度（本轮做｜差距 2、4 的一半）
| 任务 | 判据 |
|---|---|
| B1 `tracker` 加 `core_keywords`；新建监控抽屉（行业/地区/核心词/竞品/问题/渠道） | 抽屉能建出对象，字段落库 |
| B2 模型加「端」维度（网页/手机/APP），迁移 + 口径改造 | 同日同模型不同端的样本分开统计；老数据 device 默认 `web` |
| B3 采集健康 tab（采样计划 vs 实际采集，失败率） | 数字来自 `run`/`run_item`，不是编的 |
| B4 监控列表搜索、状态筛选 | 19 个对象时能筛 |

预计 3–4 人日。**B2 是数据模型变更，必须先设计再动，且要保证黄金窗口不受影响。**

### 批次 C：AI 助手 + 积分（⏸ 推迟，本轮不做）
| 任务 | 判据 |
|---|---|
| C1 积分账本（`credit_ledger`：充值/消耗/余额） | 余额 = 收入 − 支出，任何消耗都有流水 |
| C2 AI 助手抽屉（选对象/模式/目标/范围 → 后台分析） | 任务可排队、可查看进度、可取消 |
| C3 分析结果落库并回链到优化机会 | 助手产出的建议能变成「优化机会」条目 |
| C4 额度不足时的降级与提示 | 明确文案，不静默失败 |

预计 4–5 人日（不含真实 LLM 调用的成本与稳定性）。

### 批次 D：内容工作室流水线（⏸ 推迟，本轮不做）
把现有 523 行的编辑器扩成六阶段流水线。

预计 5–7 人日。

## 五、已定的范围（2026-11-24 确认）

| 决定 | 内容 | 影响 |
|---|---|---|
| **AI 体系先不做** | 批次 C/D 推迟。界面上**不出现** AI 助手入口与积分显示——不是摆着不响应 | 内容工作室保留现有形态，不扩六阶段流水线 |
| **只对齐信息架构** | 三栏、tab、双栏明细按参考做；配色与组件沿用 `theme.css` / `app.css` | 省 1–2 人日，也避免做成仿制品 |

**本轮范围 = 批次 A + 批次 B**，约 6–8 人日。

推迟的两批记在这里，不作为待办：AI 助手与积分（C）、内容工作室六阶段流水线（D）。

## 六、还没定的两件事

1. **模型 × 端（批次 B2）要不要现在加？**
   参考系统是 16 个渠道（8 模型 × 网页/手机）。加这一维要改 `sampling_plan.model_keys`、`answer.model_key` 和全部指标口径，
   是这个计划里风险最高的一步。如果暂时只有 API 采集，可以先固定 `device='web'` 占位，等真的有手机端数据再迁移。

2. **数据来源**：参考系统的「采集健康」「最近任务 15/15」依赖自己的调度。我们目前靠导入 + 缺口清单，
   所以 B3 只能先展示「计划 vs 已导入」的差额，不假装有采集链路。

## 七、我的建议

先做 **批次 A**，理由：

- 它是视频里出现时间最长的页面（44 分钟里约 30 分钟），也是用户第一眼看到的东西
- 不依赖新数据源、不碰数据模型、不推翻任何决策
- 做完之后，「我们和参考系统差多少」会变得具体，再决定要不要投 C/D 两个大批次

批次 A 内部也有顺序：A3（tab 壳）→ A4（指标看板）→ A5（双栏明细）→ A1/A2（对象列表与对象头）。先做壳，是因为壳定下来，后面每个 tab 才有地方放。
