# 008 鉴权：不引 JWT，session 放进程内存

- 日期：2026-11-24
- 状态：已采纳

## 背景

首版是「本地打开就能用」，没有任何鉴权。要给别人看（面试、同事试用）时，
这条就是硬伤：所有接口裸奔，任何人都能读改数据。

## 决策

1. **密码哈希用标准库 `hashlib.scrypt`**（N=2¹⁴, r=8, p=1），不引 bcrypt/argon2。
   哈希串写成 `scrypt$N$r$p$salt$hash`，参数自带，将来调强度不用迁移。
2. **session 存在进程内 dict**，不发 JWT、不建 session 表。
3. **接口未登录返回 401 JSON，页面返回 302 跳 `/login?next=`。**
4. **登录后租户来自会话**，忽略 `X-Tenant-Id` 请求头。
5. **提供一个显式开关 `GEO_AUTH_REQUIRED=0`**，只给自动化检查用。

## 为什么不用 JWT

JWT 的价值是无状态、可横向扩展、可跨服务校验。这里是单进程、单用户、双击启动，
三者都不需要。用了反而多两个成本：密钥管理（泄露就要换密钥并让所有 token 失效），
以及"无法主动登出"（只能靠短过期时间）。内存 session 天然支持立即登出。

## 为什么 session 不进表

进表要处理：过期清理（定时任务或惰性删除 + 索引）、并发写、备份时的敏感数据。
对一个本地工具，这些复杂度换来的只是"重启不掉线"。**明确接受重启后重新登录。**

## 为什么登录后不信任 X-Tenant-Id

如果继续读请求头，任何登录用户改个头就能看别的租户数据，等于鉴权只做了半截。
租户从会话取，请求头只在鉴权关闭（自动化检查）时作为兜底。

## 代价

| 代价 | 说明 | 补救条件 |
|---|---|---|
| 重启即掉线 | 内存 session 随进程消失 | 真要多进程/多机时换表或 Redis |
| 单账号 | 没有注册、改密、角色 | 需要多人协作时做 H4-1 |
| 默认密码写死 | `geo-demo-2026` 是演示值 | 部署到非本机前必须用 `GEO_ADMIN_PASSWORD` 覆盖 |
| cookie 未加 secure | 本地是 http | 上 https 时同时打开 `secure=True` |
| 无登录限流 | 可以暴力猜密码 | 暴露到公网前必须加（scrypt 只是让每次尝试变慢） |

## 替代方案

- **HTTP Basic**：一行代码，但没有登录页、无法登出、浏览器弹窗体验差。
- **JWT**：见上，多两个成本、少一个能力。
- **第三方 OAuth**：对外部署时再说，本地工具引外部依赖不值。
