## 决策带来的具体改动

### C-01 列表序号

- 数据模型：`mention.position_type = 'list_index'`，`position` 存列表序号（从 1 开始）。
- 解析规则：
  1. 先识别答案中的有序列表（`1.` `2.`、`-` 编号、Markdown 列表、表格行）。
  2. 品牌首次出现在某列表项内，取该项序号。
  3. 品牌只在正文段落出现、无列表 → `position = null`，计入「无列表样本」，不参与平均排名与 TopN。
  4. 一个列表项提到多个品牌 → 多个品牌共享同一序号。
- 指标口径：平均排名 = 有列表序号的提及样本的均值；TopN = 序号 ≤ N 的样本 / **有列表序号的样本**（分母不含无列表样本），同时在 UI 标注无列表样本占比。

### C-02 不实施真实采集

- 本期交付物是设计文档、数据模型、接口契约、页面信息架构，不含采集代码与代理资源。
- 方案中的 Playwright/Crawlee、会话管理、验证码处理保留为架构设计，不进入本期任务清单。
- 风险提示：真实采集的可行性（登录态、风控、DOM 稳定性）未验证，进入实现阶段前必须补一次技术验证，否则工期估算不成立。

### C-03 采样频次

- 核心：3 次/日/问题/模型；长尾：1 次/日/问题/模型。
- 3 次样本用 Wilson 区间展示提及率；1 次样本只显示点值与趋势，不显示置信区间。
- 成本估算公式：`日采样数 = 核心问题数 × 模型数 × 3 + 长尾问题数 × 模型数 × 1`。

### C-04 首版范围

- 包含：监控对象管理、问题集、指标看板（提及数/率/平均排名/TopN/情感）、问答明细、信源分布、报告导出。
- 不包含：优化机会、优化任务、内容工作室、任务发布、AI 助手。
- 首版验收只看三件事：采得到（实现阶段）、算得准、讲得清（报告）。

### C-05 人工分层

- `question.tier` 枚举：`core` / `long_tail`，默认 `long_tail`。
- 问题集支持批量标记；导入时可按行前缀（如 `*`）标记核心。
- 运营规范：核心问题建议不超过问题总数的 30%，否则成本会失控（此条为建议，不是硬约束）。
