# GEO Insight 长期计划

> 状态：2026-11-24 制定。`specs/001-geo-insight-platform/tasks.md` 是首版实现清单，本文件是**后续演进的唯一依据**。
> 工作量单位为「人日」，一个人投入 4 小时算半人日；不给日历日期，因为日历受投入强度影响，承诺日期只会变成谎言。

## 一、阶段划分

| 阶段 | 目标（一句话） | 状态 | 工作量 | 前置条件 |
|---|---|---|---|---|
| H0 能跑通 | 13 个页面接真接口，能对着面试官讲清口径 | 已完成 | — | — |
| H1 能接数据 | 从「只有种子数据」变成「能吃真实答案」 | 已完成 | — | H0 |

| H3 有一个真平台 | 真实数据自动进来，指标能对外讲 | 待启动 | 10 人日 | 平台 API 资质 |
| H4 能多人用 | 换掉单租户假设与 SQLite 单写 | 远景 | 12–15 人日 | H3 稳定运行 2 周 |

| 能力 | 交付物 | 验证 |

已知缺口（进 H2）：导入同一条观测后不能覆盖提及；采集没有调度；无鉴权。

H2-1 已交付（2026-11-24）：`--delete-batch` + `--list-batches`，004 迁移把 `status` 的 CHECK
扩到含 `rolled_back`（SQLite 只能重建表，迁移里处理了外键与可重跑）。

H2-2 已交付（2026-11-24）：`scripts/sample_gaps.py`，导出的人工清单可直接回填给导入通道，
闭环实测「缺口 60 → 填答案 → 导入 → 缺口 0」。顺带修了一个真 bug：所有指标按 UTC 日分组，
北京时间 00:00–07:59 的样本会漂到前一天，现统一为本地自然日（决策 007）。

H2-3 已交付（2026-11-24）：登录页 + scrypt 密码哈希 + 进程内 session + 中间件白名单。
接口未登录返回 401（不是 302，脚本好处理），页面跳 `/login?next=`，静态资源放行。
登录后租户取自会话、不再信任 `X-Tenant-Id`。冒烟脚本真的登录一次再跑。
自动化检查用 `GEO_AUTH_REQUIRED=0` 关闭鉴权（决策 008）。

H2-4 已交付（2026-11-24）：设置页两处删除（别名 ×、竞品「移除」）先弹确认框并写清后果；
删除与审计同一事务，审计写失败整体回滚；`audit_log.before_json` 存完整行快照。
`scripts/audit_log.py` 提供查看入口。顺带补掉一个授权洞：两个删除接口原先只按 id 操作、
不校验归属，知道 id 就能删别人的数据，现在按当前租户校验（404）。
用 CDP 做了真实点击验证：点 × 弹框 → 取消不掉数据 → 确认后删成功 → 库里留下审计。

## 三、H2 能日常用（进行中，4/7 完成，剩余 2.0 人日）

按依赖排序，前一项不做完不做后一项。

| 编号 | 任务 | 人日 | 状态 | 做完的标准 |
|---|---|---|---|---|
| H2-1 | 导入批次回滚 `--delete-batch`，级联删 answer/mention/citation | 0.5 | **已完成** | 回滚后三表计数回到导入前；批次状态 `rolled_back`；撤完可重导 |
| H2-2 | 缺样本清单：按采样计划算出「今天该采哪些」还差几条，导出 CSV，导入后自动核销 | 1.0 | **已完成** | 导出条数 = 应有 − 已有（已断言）；闭环后缺口归零（已端到端验证） |
| H2-3 | 最简鉴权：登录页 + session cookie + 中间件白名单 | 1.5 | **已完成** | 无 cookie 访问 `/v1/*` 返回 401；登录后 200；静态页可访问 |
| H2-4 | 删除二次确认 + 审计落库（`audit_log` 真正写入） | 0.5 | **已完成** | 删除在 `audit_log` 留 before；审计失败整体回滚；跨租户删不动 |
| H2-5 | 趋势按周聚合（`granularity=week`） | 1.0 | 待做 | 周值 = 对应 7 个日值之和，误差 0（写断言） |
| H2-6 | 问题集与监控对象绑定（一对象多问题集，可切换） | 0.5 | 待做 | 切换后问题列表与指标口径同步变化 |
| H2-7 | 引用类型筛选（inline/reference/video 生效到接口与页面） | 0.5 | 待做 | 筛选后条数与手工 SQL 一致 |

**为什么 H2-2 排在鉴权前面**：现在没有 API 权限，最现实的日常动作是「人工去三个平台各问一遍，导出结果再导进来」。缺样本清单直接决定这套流程能不能跑通，比登录更值钱。鉴权排第三是因为它只影响「能不能给别人看」，不影响自己用。

**H2 结束时的验收**：连续 3 天按缺样本清单导出 → 人工采集 → 导入 → 指标更新，全程不需要碰数据库；一键 reset 仍能回到演示态。

## 四、H3 有一个真平台（10 人日，取决于外部条件）

| 编号 | 任务 | 人日 | 说明 |
|---|---|---|---|
| H3-1 | 平台准入调研（非代码） | 1.0 | 豆包 / DeepSeek / Kimi 的企业资质、价格、限流、**是否允许存储原始回答** |

| H3-3 | 采集调度器（进程内循环 + 幂等键） | 1.5 | 幂等键 (问题, 模型, 日期, 样本序)；重复调度不产生重复样本 |
| H3-4 | 失败重试 + 失败率告警 | 1.0 | 复用 `sampling_failure_threshold`，失败原因可分类型统计 |
| H3-5 | 提及识别 v1（规则 + 人工校正入口） | 2.0 | 品牌名/别名精确与归一化匹配；识别结果可一键清空重跑 |
| H3-6 | 原始响应存档 | 1.0 | `raw_uri` 从 `s3://geo-raw/demo/` 换成真实可回溯路径 |
| H3-7 | 连续 3 天真实采样观察 | 1.5 | 每天 0.5 人日，看数据质量与失败分布 |

**H3 结束时的验收**：
- 单平台 10 问题 × 3 天 × 3 次 = 90 条真实答案入库，`raw_uri` 全部可回溯；
- 采集失败率 < 10%，失败原因有分类统计；
- 提及识别在 30 条人工标注样本上准确率 ≥ 80%，漏检清单可导出；
- 基于真实数据生成的报告可复现（`payload_hash` 一致）。

**这一步的真正风险不是代码，是资质。** 如果 H3-1 结论是「必须企业主体 + 对公账户」，那 H3 就要推迟，改为把 H2-2 的人工流程做扎实，用「人工采集 + 导入」撑住产品价值。

## 七、每个阶段都适用的硬约束

1. **回归闸门**：改动后必须过 308 项（单测 97 / 冒烟 80 / 页面契约 77 / 浏览器 32 / 分页 22），黄金窗口 22.22%、9 样本、-23.3pp 等 19 项手算值不许动。
2. **结构变更只走迁移**：已应用的迁移文件不许改（checksum 会拦），改结构就新增版本号。
3. **关键断言必须变异自检**：故意改错实现，确认检查会变红；红不了说明这条断言没在验证任何东西。
4. **诚实标注验证层级**：只到「能跑通」就写「行为未验证」，不用「应该可以了」收尾。
5. **新增限制要同步 README**：做了半截的能力，写进「尚未实现」，不靠口头记忆。
6. **日期一律按本地自然日**：按天分组用 `sqlutil.day_of()`，不要用 SQLite 的 `date()`——它会把带偏移的时间转成 UTC，北京时间 00:00–07:59 的样本会漂到前一天（决策 007）。

## 十、节奏

- **单任务**：定判据 → 实现 → 变异自检 → 跑全量 → 提交（说明改了什么/为什么/验证到第几层/还有什么没验）。
- **每周**：更新本文件的阶段状态；把当天踩的坑写进 `.workbuddy/memory/`。
- **每阶段结束**：把「尚未实现」清单里已消项的条目删掉，把新出现的限制补进去。
