## 2026-11-24：从"能演示"到"能接数据"（P0 三件事）

用户第一天入职，批准了 P0 计划。本轮把系统从「只有种子数据」推进到「能吃真实数据」。

### 做了什么

- **git 基线**：项目此前不是仓库，先 `git init` + `.gitignore`（`*.db` 不入库，数据由 seed 重建），
  把 247 项全绿的可用状态提交为基线，后面每个迁移都有回滚点。
- **迁移链**（`backend/migrations/` + `geo/migrate.py`）：版本表 + checksum 校验 + 老库基线认领。
  老库认领是刚需——`backend/geo.db` 里有 1510 条演示数据，不能为了改结构就删库。
  已应用迁移被改动、文件被删、版本号重复、中途失败后修好重跑，都有明确报错。
- **导入通道**（`import_service` + `scripts/import_answers.py`）：中英文表头、时间/数值/JSON 校验、
  失败行报告（UTF-8 BOM，Excel 直接开）、`--dry-run` / `--on-error abort` / `--create-questions`。
  幂等靠 `answer.row_hash` 部分唯一索引 + 应用层预查，双保险。
- **采集器协议**（`collectors/`）：`Collector` 协议 + 显式注册表 + 离线 `csv_bank` 实现。
  没有平台 API 权限，所以不写假的 api adapter 冒充能联网。
- **启动修复**：`run.py` 用硬编码 `geo.db` 判存在、却读 `GEO_DB_PATH` 的库，两者不一致就崩。

### 两个真 bug（都是"数据一变就露馅"的类型）

1. **竞品被认成本方**（严重，影响指标正确性）
   - 现象：导入 3 条（2 条本方 + 1 条竞品），接口返回 mention_count=3、avg_rank 分母=2。
   - 根因：`mention.brand_id` 外键指向 `brand`，导竞品提及时必须给竞品建 brand 行；
     而 `load_subjects` 把所有 brand 行都当"本方"。第二次导入同一个竞品，按名字查出来就是 own。
   - 修法：给 `brand` 加 `kind`（迁移 003），subject_type 读数据库而不是靠"在不在 brand 表"推断；
     同时把已写错的 `mention.subject_type` 一并纠正。
   - 教训：**凡是"从数据形状反推语义"的地方，迟早会反推错。语义要显式落到列上。**
   - 种子数据里没有一条竞品提及，所以既有 247 项检查全绿也没拦住——**回归全绿不等于新路径正确**。

2. **双击启动可能抛 `no such table`**
   - 根因同上一类：判据（`Path("geo.db").exists()`）与真实数据源（`settings.database_path`）不是同一个。
   - 修法：判据改成"有没有配置过监控对象"，只认 settings 一个来源；空库/新库都走 seed。

### 验证到第几层

- **命令层**：全部脚本可跑，退出码分层（0 全成功 / 2 有失败行 / 1 无法开始）。
- **行为层**：285 项全绿（单测 74 + 冒烟 80 + 页面契约 77 + 浏览器 DOM 32 + 分页 22）。
  四个关键断言做了**变异自检**，确认不是摆设：
  - 去掉 checksum 校验 → 篡改测试变红
  - 去掉 row_hash 去重 → 幂等测试变红（且唯一索引兜底，抛 IntegrityError）
  - dry-run 的 `rollback` 改成 `commit` → 演练测试变红
  - `load_subjects` 退回"一律 own" → 竞品回归测试变红
- **意图层**：
  - 真实 CSV/JSONL 导入 → 查库确认提及/引用/位次类型/brand 自动建行都对；
  - 起服务查接口：2027-01-05（种子无此日）valid_total=3、提及率 66.67%、avg_rank 样本不足；
  - **全新库首次启动**（删掉 db 文件）→ 迁移建 25 张表、seed 1510 条、黄金窗口 22.22%/9 样本一字不差。
- 黄金窗口 19 项手算值未动。

### 新踩的坑

- `bash` 的 `/tmp` 与 Python 眼里的 `/tmp` 不是同一个目录（前者在 `C:\Users\...\AppData\Local\Temp`，
  后者在 `C:\tmp`）。用 `/tmp/x.db` 传给 Python 会在 `C:\tmp` 建一个新空库，验证结果全是假的。
  跨语言传路径一律用绝对 Windows 路径。
- `backend/.venv` 是空壳（只有 pip）。`start.bat` 用的是系统 Python（uvicorn 在那儿）。
  跑需要依赖的脚本（run.py/smoke.py）必须用系统 `python`，只有标准库的测试才可以用 `.venv`。
- 用错了接口参数名（`start/end` vs `from/to`），两次查询都落到默认最近 7 天，得出"两组日期结果相同"的假结论。
  查询类验证要先用一个必然为空/必然有值的区间做哨兵。

### 已知限制（写进 README「尚未实现」）

- 导入同一条观测后，不能靠重新导入覆盖提及/引用（会被判重复），要手工删行；`--delete-batch` 未做。
- 采集器只有离线实现；`mention` 没有自动识别器，靠 seed 或导入时的字段。
- 无鉴权；无 down migration；无周聚合。

## 2026-11-24 下午：H2-1 导入批次回滚

- **需求来源**：导入通道自己的缺口——同一条观测入库后靠重导改不动（会被 row_hash 判重复），标错提及只能手工删库。
- **交付**：`--list-batches` / `--delete-batch <id> [--dry-run]`；级联删 citation→mention→answer_block→answer；批次状态 `rolled_back`。
- **迁移 004 的难点**：SQLite 不能 ALTER CHECK，只能重建表。重建时处理了三件事：可重跑（查 sqlite_master 里是否已有 rolled_back）、外键（重建期间 PRAGMA foreign_keys=OFF，结束必须打开）、失败残留（先 DROP import_batch_new）。`INSERT INTO new SELECT *` 能成立的前提是列顺序与 002 完全一致。
- **刻意的取舍**：竞品的 `brand` 行不随批次删——那是"主体注册"，可能被别的批次的提及引用。测试 `test_rollback_keeps_subject_registry` 把这条锁住。
- **重复回滚是幂等而非报错**：脚本重跑不该因为"已经撤过了"就红。
- **验证**：单测 84（+7 回滚 +3 迁移重建）/ 冒烟 80 / 页面契约 77 / 浏览器 32 / 分页 22 = 295 全绿；黄金窗口未动。
- **变异自检两处**：①回滚只标记不删答案 → 4 条测试红；②删除条件去掉 batch 限制 → "只动自己批次"那条红。
- **踩坑**：`--list-batches` 最初对已回滚批次仍显示"新增 3"，会让人误以为数据还在；改成"0（曾 3）"。

## 2026-11-24 下午：H2-2 缺样本清单（+ 一个日期口径真 bug）

- **需求**：没有 API 权限时，日常动作是「算缺口 → 人工去问 → 导回结果」。核销不建待办表，纯实时差分。
- **交付**：`scripts/sample_gaps.py`（单日/区间/按模型/`--export`/`--json`/`--fail-on-gap`）；导出的 CSV 用中文表头且列名就是导入通道认的那几个，填完直接导回。
- **闭环实测**：缺口 60 → 导出 → 填 60 条答案 → 导入 → 缺口 0。
- **顺带修的真 bug（比需求本身值钱）**：所有指标用 SQLite `date(collected_at)` 分组，而 `date()` 会把带 +08:00 的时间先转 UTC。`2026-11-20T00:30:00+08:00` → 返回 `2026-11-19`，即北京时间 00:00–07:59 的样本会漂到前一天。10 处查询统一改为 `substr(...,1,10)`（`repositories/sqlutil.day_of()`），用 decision 007 记录取舍。
- **为什么现在才发现**：种子数据全在 09:00（转 UTC 是 01:00，同一天），一直没露馅。做缺口清单时"按本地日算"与"看板按 UTC 日算"必须一致，才把它顶出来。**新功能常常是旧 bug 的显影剂**。
- **验证**：308 项全绿（单测 97 / 冒烟 80 / 页面契约 77 / 浏览器 32 / 分页 22）；黄金窗口 22.22%/9 样本未动（改的是分组表达式，种子数据同一天，所以结果不变——但必须实测确认，不能推）。
- **变异自检两处**：①`missing = expected - actual`（允许负缺口）→ 1 条红；②core/long_tail 次数对调 → 6 条红。
- **踩坑**：按字符数截断中文列会让表格错位，得按显示宽度（`unicodedata.east_asian_width`）截。
- **踩坑**：两次想用 Edit 做"空操作"结果吃掉了换行，把函数定义和 docstring 挤成一行。以后改文件只做真正的替换。

## 2026-11-24 傍晚：H2-3 最简鉴权

- **交付**：登录页 + scrypt 密码哈希 + 进程内 session + 中间件白名单；侧栏底部「退出登录」。
- **关键取舍**（决策 008）：不上 JWT（单进程单用户，多两个成本少一个能力：主动登出）；session 不进表（重启掉线是可接受代价）；接口 401、页面 302（脚本跟着跳到 HTML 更难查）。
- **顺手补的一个授权洞**：登录后 `_tenant` 仍会读 `X-Tenant-Id`，等于任何登录用户改个头就能看别人数据。改成租户只从会话取，请求头仅在鉴权关闭时兜底。**认证做完不等于权限做完。**
- **测试策略**：TestClient 走真实 ASGI 栈，覆盖 401/302/cookie 属性（HttpOnly/SameSite）/登出/开放重定向/租户伪造。
- **冒烟脚本改成真登录**：`http.cookiejar` + `install_opener`，登录一次后续全带 cookie；新增 6 条断言。踩坑：`urlopen` 默认跟随 303，观察不到 Location，得用一个不跟随的 opener —— 但它必须同时挂 CookieProcessor，否则登录成功也存不下 cookie。
- **空 venv 坑**：`backend/.venv` 只有 pip，starlette 在系统 Python。HTTP 层测试用系统 python 跑，空 venv 里会整模块 SkipTest 并说明原因。README 写清了「用系统 Python」。
- **自动化检查的鉴权**：pagecheck/browsercheck 会先探一次接口，401 就打印「用 GEO_AUTH_REQUIRED=0 启动后再跑」并退出 1，不让 13 页全红让人猜。
- **验证**：336 项全绿（单测 119 / 冒烟 86 / 页面 77 / 浏览器 32 / 分页 22）。变异自检两处：①中间件无条件放行 → 3 条红；②租户改回信任请求头 → 1 条红。Chrome 截图确认登录页居中、无溢出；curl 确认登录后侧栏出现且只有一个退出入口。

## 2026-11-24 晚间：H2-4 删除二次确认 + 审计落库

- **需求**：`audit_log` 表从第一版就在，从没写入过。有了登录态才能记「谁删的」。
- **事务边界是这次的核心**：repository 的 `remove_*` 原本自己 commit，那样「删除成功、审计失败」会留下删了没记账。改成返回被删快照 + `commit=False`，由 API 层统一提交，异常时 rollback。
- **一条判据**：审计写失败 → 删除必须回滚。测试用 mock 让 record 抛异常，断言 alias 还在。
- **顺带补的授权洞**：两个删除接口只按 id 操作、不校验归属，登录用户知道 id 就能删别人家的别名/竞品。现在按会话租户校验。**这和 H2-3 那个 X-Tenant-Id 是同一类问题：认证做完不等于授权做完，删除类接口尤其要单独想一遍。**
- **前端**：复用页面已有的 `<dialog>` 模式做确认框（不引 confirm()），文案写后果（「历史提及不会改变」/「集合版本号加一」）而不是「确定吗」。
- **验证手段升级**：Node 22 有全局 WebSocket，用 CDP（--remote-debugging-port）做了真实点击验证 —— 点 × → 弹框 → 取消不掉数据 → 确认 → 删除成功 → 库里留审计。这是第一次真正验证"点了按钮会发生什么"，比 dump-dom 强一档。脚本是临时的，值得后续参数化成 `scripts/clickcheck.mjs`。
- **踩坑（重要）**：变异注入用长字符串 `replace` 会静默失败（`count` 为 0 但脚本不报错），导致"变异后测试仍通过"的假结论。必须 `assert count == 1` 或注入后 grep 确认。这次是靠先打印命中次数才发现。以后变异脚本一律「先断言注入成功，再跑测试」。
- **取舍**：`ACTIONS` 里只登记真正在用的两个动作。原本预写了 import.rollback 等三个，但没实现——留着会让读代码的人以为回滚也有审计。改法：删掉未实现的，在注释和 README 里写明待接。
- **验证**：351 项全绿（单测 134 / 冒烟 86 / 页面 77 / 浏览器 32 / 分页 22）。黄金窗口 22.22%/9 样本未动。
