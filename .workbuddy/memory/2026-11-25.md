   测试没造文章所以没暴露。**级联删除的顺序缺陷，只有造了全量数据的测试才能发现。**

## 11:40–12:10 试点 D2：真实采集 adapter（DeepSeek + 豆包）

**为什么跳过 D1**：D1 要用真 key 跑 6 次调用，这台机器上没有任何 key（无 .env、无环境变量）。
D2 的四条判据里三条能离线验证，所以先把代码写完，拿到 key 一次性跑 D1+D2 的真调用。

**DeepSeek 的坑（最容易漏的一条）**：citation 里**只有 url/title/cited_text**，
没有 site_name、没有发布时间。这两个字段在另一个块 `web_search_tool_result.content[]` 里（site_name / page_age）。
必须按 URL 回填。不回填的话，库里每条引用的媒体名和发布时间全是空，
「信源分布」「发布时间完整度」两个 tab 会变成一片空白——不是没数据，是丢了。
变异自检：把回填改成 None，`test_citation_backfilled_from_search_result` 立刻红。

**search_called 必须是三态，不能是布尔**：
- 1 搜了 / 0 明确没搜 / NULL 不知道（导入通道和历史数据）
- 若 `NOT NULL DEFAULT 0`，「不知道」会被算成「没搜」，搜索触发率被系统性算低。
- 「没搜索」与「搜了没引用」的处理方式完全不同：前者改问法，后者改内容。
  只有布尔值时这两种 0 引用会混成一个数字，D1 的「2/3 次触发搜索」就没法判。
- 变异自检：把 `search_called = bool(search_blocks) or bool(usage_search)` 改成
  `bool(citations)`，两条测试同时红（解析层 + 落库层）。

**顺手修的两个真问题**：
1. `collect_service` 用 `registry.first_available()` 挑采集器 → 加了两个真实采集器后，
   采 doubao 会拿到 deepseek，直接报 UNSUPPORTED_MODEL。新增 `registry.for_model()`：
   按「可用且支持」筛，并且 api 优先于 offline（配了 key 就该采真数据，不能悄悄退回旧答案）。
2. 豆包 Chat API 里 `tools` 与 `web_search_options` 同时传时**联网不生效**（官方文档明写）。
   加了断言 `assertNotIn("tools", payload)`——这条守的是"别顺手把 tools 加回来"，
   加了以后采集照常成功、只是永远不搜索，从结果上完全看不出来。

**两次踩到"别人也在动同一个仓库"**：
- 全量单测出现随机 500 / 切换不生效。查到 PID 18160 正在跑同一个测试套件，
