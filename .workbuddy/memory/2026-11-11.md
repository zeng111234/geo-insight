- 切换 Spec Kit 项目必须跑 wire 脚本，只 `specify init` 不够：用户级技能里硬编码了项目根，
  不切换的话 `/speckit-*` 会把产物写进上一个项目。
- Windows 版 Python 与 Git Bash 的 `/tmp` 不是同一路径；用 shell 重定向到 /tmp 再让 Python 读会假失败，
  验证时直接用 subprocess 捕获 stdout 更可靠。

## 2026-11-11 深夜八：修「start.bat 报错」+ 面试可用性

- 定位到两个真原因（不是猜测）：① 我自己在后台跑着服务占着 8123，用户双击 start.bat 撞端口，被当成 `[x] 端口已被占用` 的失败并 `pause` 停住；② start.bat 是 **LF 换行**（0 个 CRLF），Windows 批处理该用 CRLF，部分环境会报「命令语法不正确」。
- 修法：`run.py` 端口占用时先探 `/health`，若是本服务则**直接开浏览器并返回 0**（重复双击不再报错）；start.bat 改为 **纯 ASCII + CRLF**，用 `where python` → `where py` → 常见安装路径三级兜底，避免资源管理器 PATH 差异。
- 新增：两页在 `file://` 下插入琥珀色提示条，明确「双击 start.bat 再访问 127.0.0.1:8123」，不再只留一句 Failed to fetch。
